# 归档模块 - 详细设计

## 1. 可能存在的问题

- 文件归档过程中，文件变化
- 如果为了避免文件变化，而采用快照或者镜像的方式，那么大文件要如何处理，如果一个已经 100 G 的文件呢？
- 如何支持来源是多目录的文件归档，以及如何配置文件

### 1.1. Q1

如果在程序关闭期间，文件目录发生了变化，但是文件没有变化，如何避免文件的重新归档？

程序并不会识别目录移动或是更名，而是认为这个目录被删除了，并且新增了一个目录，只要文件保持一致，文件索引表中仅 directory_id
等属性会被更新

## 2. 第一次运行程序

TODO: 此处没有考虑写入期间文件发生改变的情况

1. 添加或记录配置
2. 创建 JSON 配置文件
3. 创建索引表
4. 获取文件列表
5. 将目录列表写入目录布隆过滤器，以及写入目录索引表和闭包表
6. 将文件列表写入文件布隆过滤器，写入索引表
7. 按照文件列表将修改时间大于配置时间 (例如 30 分钟没有修改的文件) 添加到归档中，并更新归档表
8. 将修改时间小于配置时间的文件克隆到临时目录

## 3. 程序启动时（初始化）

1. 【第一次运行】创建配置文件，索引表
2. 读取配置文件（sqlite）
3. 读取索引表
4. 读取文件列表（根据配置是否计算 hash）
5. 对比文件列表
6. 修改索引表
7. 把文件添加到 tar 归档
8. 【可选】压缩归档
9. 【可选】对归档文件进行加密

从 file_index 表中读取文件列表，然后逐一把文件使用 hash 重命名后 添加到 tar 归档中，同时将信息写入 file_index 表

## 4. 程序运行期间

保持同步与追踪，如果大于配置时间没有修改，则写入归档

## 5. 按场景的详细设计

### 5.1. 场景一：用户指定目录进行归档

1. 用户提供指定目录
    1. 若目录已经存在在归档目录列表中，增量归档
    2. 否则创建新的归档
2. 程序创建索引表以及归档文件

### 5.2. 场景二：用户解档指定的目录

1. 用户从归档目录列表中指定需要解档的目录
2. 用户选择解档目标的根目录
3. 程序还原目录树，并将归档中的文件恢复到目标目录中

- 需要维护一个归档目录列表
  - 每次归档的时候需要添加一个目录
  - 每次解档的时候，用户需要选择一个目录

### 5.4. 场景三：把文件存储到归档中

- 存在两类文件：完整存放到归档中; 需要分卷存放到多个归档中
- 文件分卷的原因：原有的归档存储空间不足，

1. 需要维护几个类变量：归档的限制体积，当前归档的体积，归档的编号

- 加载文件列表
- 遍历文件列表
- 获取文件大小
- 判断是否需要分卷

1.​​是否需要保留文件的元数据​​（如权限、所有者、修改时间）？是
2.​​是否需要支持压缩​​（如 gzip/bzip2）？若需要，是否接受分卷大小因压缩率波动而超过上限？是，接受
3.​​如何处理超过单卷大小的单个文件​​（如 10G 文件，单卷上限 5G）？是否需要拆分文件？拆分文件
4.​​是否需要过滤特定类型的文件​​（如.tmp、隐藏文件）？否
5.​​分卷文件的命名规则是否需要调整​​（如前缀、编号位数，如 archive_1.tar vs archive_001.tar）？推荐 archive_001.tar
