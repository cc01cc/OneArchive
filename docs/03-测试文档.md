# 测试文档

## 1. 扫描功能

扫描功能，主要校验的是数据库记录是否正确 (记录是否存在，记录的 status 是否正确)

### 1.1. 场景

1. 新的归档
2. 增量归档 (需要额外校验，被删除或修改的文件，对应记录是否删除或更新)
3. 已经存在若干个归档，再添加独立的新的归档
4. 两个包含关系的归档

### 1.2. 详细测试场景和预期结果

为了确保扫描功能的正确性，我们需要覆盖以下详细的测试场景：

| 场景 ID | 场景描述            | 操作步骤                                                  | 预期结果                                                                                                                            |
| ------- | ------------------- | --------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| T01     | 首次扫描新目录      | 1. 创建新目录结构<br>2. 执行扫描                          | 1. 所有新记录状态为 WaitToArchive<br>2. 根目录状态为 WaitToScan -> InScanning -> WaitToArchive<br>3. 数据库中创建所有目录和文件记录 |
| T02     | 增量扫描 - 无变更   | 1. 执行首次扫描<br>2. 再次执行扫描 (无文件变更)           | 1. 所有现有记录状态为 Health<br>2. 无新记录创建<br>3. 无记录删除                                                                    |
| T03     | 增量扫描 - 文件修改 | 1. 执行首次扫描<br>2. 修改部分文件内容<br>3. 执行增量扫描 | 1. 修改的文件状态为 WaitToArchive<br>2. 未修改文件状态为 Health<br>3. 所有目录状态为 WaitToArchive                                  |
| T04     | 增量扫描 - 新增文件 | 1. 执行首次扫描<br>2. 添加新文件<br>3. 执行增量扫描       | 1. 新文件状态为 WaitToArchive<br>2. 现有文件状态为 Health<br>3. 包含新文件的目录状态为 WaitToArchive                                |
| T05     | 增量扫描 - 新增目录 | 1. 执行首次扫描<br>2. 添加新目录及文件<br>3. 执行增量扫描 | 1. 新目录状态为 WaitToArchive<br>2. 新目录中的文件状态为 WaitToArchive<br>3. 现有记录状态为 Health                                  |
| T06     | 增量扫描 - 删除文件 | 1. 执行首次扫描<br>2. 删除部分文件<br>3. 执行增量扫描     | 1. 删除的文件状态为 WaitToDelete<br>2. 未删除文件状态为 Health<br>3. 目录状态为 WaitToArchive                                       |
| T07     | 增量扫描 - 删除目录 | 1. 执行首次扫描<br>2. 删除整个目录<br>3. 执行增量扫描     | 1. 删除目录及其中所有文件状态为 WaitToDelete<br>2. 其他记录状态为 Health                                                            |
| T08     | 多个独立归档        | 1. 扫描目录 A<br>2. 扫描目录 B(与 A 无关)                 | 1. 两个独立的根目录记录<br>2. 各自的目录和文件记录互不干扰<br>3. 所有记录状态正确                                                   |
| T09     | 包含关系的归档      | 1. 扫描父目录<br>2. 扫描子目录                            | 1. 两个独立的根目录记录<br>2. 子目录的记录在两个归档中都存在<br>3. 状态管理正确                                                     |

### 1.3. 数据库操作验证点

在每个测试场景中，我们需要验证以下数据库操作点：

1. **根目录表 (info_root)**
   - 根目录记录正确创建
   - 根目录状态正确更新 (WaitToScan -> InScanning -> WaitToArchive -> InArchiving -> Health)
   - 多个根目录之间互不干扰

2. **目录表 (info_directory)**
   - 目录记录正确创建
   - 目录状态正确更新 (WaitToArchive <-> InArchiving <-> Health, WaitToDelete)
   - 父子目录关系正确维护

3. **文件表 (info_file)**
   - 文件记录正确创建
   - 文件状态正确更新 (WaitToArchive <-> InArchiving <-> Health, WaitToDelete)
   - 文件与目录的关联关系正确

4. **视图 (view_file)**
   - 能正确查询文件及其目录信息
   - 状态过滤功能正常

## 2. 归档功能

归档功能，主要校验的是数据库记录状态是否正确更新，以及文件是否正确归档

### 2.1. 场景

1. 首次归档
2. 增量归档
3. 大文件归档
4. 小文件归档
5. [TODO]多个归档任务并行处理

### 2.2. 详细测试场景和预期结果

为了确保归档功能的正确性，我们需要覆盖以下详细的测试场景：

| 场景 ID   | 场景描述         | 操作步骤                                                     | 预期结果                                                                                                                                           |
| --------- | ---------------- | ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| A01       | 首次归档         | 1. 扫描新目录<br>2. 执行归档                                 | 1. 根目录状态为 WaitToArchive -> InArchiving -> Health<br>2. 所有目录和文件状态为 WaitToArchive -> InArchiving -> Health<br>3. 文件被正确归档      |
| A02       | 增量归档         | 1. 扫描目录<br>2. 修改部分文件<br>3. 重新扫描<br>4. 执行归档 | 1. 仅修改的文件状态从 WaitToArchive -> InArchiving -> Health<br>2. 未修改文件状态保持 Health<br>3. 相关目录状态正确更新<br>4. 修改的文件被正确归档 |
| A03       | 大文件归档       | 1. 扫描包含大文件的目录<br>2. 执行归档                       | 1. 大文件状态为 WaitToArchive -> InArchiving -> Health<br>2. 归档过程中正确记录进度<br>3. 大文件被正确归档                                         |
| A04       | 小文件归档       | 1. 扫描包含小文件的目录<br>2. 执行归档                       | 1. 小文件状态为 WaitToArchive -> Health (跳过 InArchiving)<br>2. 小文件被正确归档                                                                  |
| [TODO]A05 | 多个归档任务并行 | 1. 创建多个归档任务<br>2. 同时执行归档                       | 1. 各任务独立执行<br>2. 各任务状态正确更新<br>3. 所有文件被正确归档<br>4. 任务间互不干扰                                                           |
| A06       | 归档过程中断     | 1. 开始归档<br>2. 中断归档过程<br>3. 重新执行归档            | 1. 中断前已完成的文件状态为 Health<br>2. 未完成的文件状态为 WaitToArchive<br>3. 重新执行能继续完成归档                                             |
| A07       | 归档失败处理     | 1. 扫描目录<br>2. 模拟归档失败<br>3. 重新执行归档            | 1. 失败文件状态为 ErrorArchivingFailed<br>2. 重新执行能正确处理失败文件<br>3. 最终所有文件状态为 Health                                            |

### 2.3. 数据库操作验证点

在每个测试场景中，我们需要验证以下数据库操作点：

1. **根目录表 (info_root)**
   - 根目录状态正确更新 (WaitToArchive -> InArchiving -> Health)
   - 异常情况下状态正确更新 (ErrorArchivingFailed)

2. **目录表 (info_directory)**
   - 目录状态正确更新 (WaitToArchive -> InArchiving -> Health, ErrorArchivingFailed)
   - 父子目录状态更新顺序正确

3. **文件表 (info_file)**
   - 文件状态正确更新 (WaitToArchive -> InArchiving -> Health, ErrorArchivingFailed)
   - 小文件可能跳过 InArchiving 状态直接到 Health 状态
   - 文件与目录的关联关系正确

4. **视图 (view_file)**
   - 能正确查询文件及其目录信息
   - 状态过滤功能正常
   - 能正确区分已归档和未归档文件

5. **归档文件存储验证**
   - 归档文件正确存储在指定位置
   - 归档文件内容与原文件一致
   - 重复文件不会重复存储（去重机制）

### 2.4. 本地文件验证点

在每个测试场景中，我们需要验证以下本地文件操作点：

1. **归档目录结构验证**
   - 归档目录在归档开始前为空目录
   - 归档完成后，归档目录中包含正确组织的文件结构
   - 归档目录中的文件命名符合预期规则（基于哈希值）

2. **文件内容验证**
   - 归档文件内容与原始文件内容一致（通过哈希值校验）
   - 大文件分卷存储正确，能够完整还原
   - 小文件直接存储，不进行分卷处理

3. **重复文件处理验证**
   - 相同内容的文件只在归档目录中存储一份
   - 不同目录中的相同文件在归档中引用同一份文件
   - 文件去重机制正确工作，节省存储空间

4. **文件权限和元数据验证**
   - 归档文件具有正确的访问权限
   - 文件的修改时间等元数据正确保存
   - 归档文件的创建时间与归档执行时间一致

5. **异常情况下的文件验证**
   - 归档中断后，已归档的文件保持完整可用
   - 归档失败的文件不会产生不完整的归档文件
   - 重新归档时，能够正确处理已存在的归档文件

### 3.3. 本地文件验证点

在每个测试场景中，我们需要验证以下本地文件操作点：

1. **目标目录结构验证**
   - 解档后目标目录结构与原始目录结构一致
   - 目录权限和属性正确设置
   - 嵌套目录正确创建

2. **文件内容和属性验证**
   - 解档后的文件内容与原始文件一致（通过哈希值校验）
   - 文件修改时间正确设置
   - 文件访问权限正确设置

3. **特殊文件处理验证**
   - 空文件正确解档
   - 隐藏文件正确解档
   - 只读文件正确解档

4. **分卷文件处理验证**
   - 分卷文件正确识别和合并
   - 合并后文件完整性得到保证
   - 合并过程中不产生临时文件残留

5. **异常情况处理验证**
   - 归档文件损坏时的错误处理
   - 磁盘空间不足时的错误处理
   - 目标目录无写权限时的错误处理
